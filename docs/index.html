CircleCI runner job wrapper

Which job ran on which host

A small bash wrapper for the CircleCI machine runner command_prefix. It records the host, runner agent and resource class of every job, with the CircleCI job, workflow and pipeline IDs, so you can join CircleCI OpenTelemetry spans with host metrics and logs.

Set it up end to end View on GitHub

Why use the job wrapper

  • Host identity on every job

    EC2 instance, runner agent and resource class, next to the job, workflow and pipeline IDs and links.

    Event schema

  • Joins CircleCI spans with host data

    The job ID matches com.circleci.job.id on CircleCI spans, and the instance ID matches your host metrics.

    Join the data

  • Never changes the job

    The task agent runs as a normal child. Stdin, signals and the exit status pass through, and a logging failure never fails a job.

    How it works

  • No dependencies

    One bash script, no daemon and no jq. About 6 ms per job.

    Install

  • Any backend

    JSONL on disk. Alloy example tested with Grafana Cloud, Datadog Agent documented, plus an example Grafana dashboard.

    Ship the data

What you need

Only the first group is required. The wrapper works with nothing else.

WhatNotes
RequiredThe wrapper script bin/circleci-job-wrapper and a command_prefix entry in the runner configMachine runner 3.1.11 or later, on Linux
RequiredA log directory the runner user can writeDefault /var/log/circleci-job-wrapper
RecommendedThe boot-time host cache systemd unitGives every job its EC2 identity without a metadata call per job. IMDS must be enabled, and IMDSv2 works
RecommendedThe logrotate configRotates jobs.jsonl daily
RecommendedThe operator file /etc/circleci-job-wrapper/wrapper.env with CCI_RESOURCE_CLASSThe runner does not tell the wrapper its resource class
OptionalCircleCI org OpenTelemetry exportSpans for job and step timing and the job result. The wrapper adds the host
OptionalPrometheus busy gauge (CCI_JOBLOG_PROM_DIR)A live busy or idle view per runner
OptionalHTTP sink (CCI_JOBLOG_HTTP_URL)POST every event to an endpoint
OptionalA shipper: the Grafana Alloy example, the Datadog Agent, Vector, Fluent Bit and othersMoves jobs.jsonl to your backend
Optional, experimentalThe task-agent journal pipelineLive step progress and the job result per host. The internal log format may change
OptionalThe example Grafana dashboardsNeed Alloy, Grafana Cloud or similar
